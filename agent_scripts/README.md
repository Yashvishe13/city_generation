# agent_scripts/

Everything under this directory is **generated by the coding agent**, one directory per
area, and is not maintained by hand.

The pipeline for an area is written fresh when that area is chosen. The agent loads the
contract skills (`osm:pipeline-plan`, `osm:pipeline-shape`, `osm:scene-contract`,
`osm:coordinates`, `osm:fetching`, `osm:inspection`, `osm:estimation`), measures the area
with code it writes itself, and produces a self-contained pipeline that goes from
OpenStreetMap through to `data/ue/<area>/scene.json`.

That means constants inside a pipeline are area-specific on purpose. A storey height or
lane width fitted from Manhattan belongs in the Manhattan pipeline; choosing Paris
produces a different pipeline with different numbers, because it was fitted on Paris.

Each generated pipeline:

- **runs standalone**: `python3 agent_scripts/<area>/pipeline.py --area <area>`, on a
  clean checkout with an empty `data/raw`. It does its own Overpass fetch; no tool has to
  run first.
- **runs anywhere**: no absolute path in the file or in anything it writes. The repo root
  comes from `--repo`, `CITYGEN_REPO`, or the file's own location.
- **is deterministic**: the same input produces byte-identical output.
- **caches its download**, so re-runs do not re-hit the API. `--force` re-downloads.
- **self-checks**: `--verify` asserts and exits non-zero on failure. Then
  `tools/verify_area.sh <area>` checks the result against the original OSM extract rather
  than against the pipeline's own manifest.

Each directory also holds the `PLAN.md` the agent wrote before the code — the inventory
it measured, the mapping it chose, what it fitted and from what sample size, and what it
deliberately excluded.

The prompt that produced each pipeline is in `docs/agent-prompts/`.
